# 游戏客户端开发者人设接入

## 角色来源

内置模板 `xiaojingyu_game_client` 的名称为“小鲸鱼（游戏客户端开发者）”。
正文的唯一源码是 [roles/xiaojingyu-game-client.md](../roles/xiaojingyu-game-client.md)，
由 `src/personas.js` 使用相对模块 URL 加载，不依赖启动工作目录。
部署时必须带上 `roles/`；仓库的完整部署同步会包含该目录。

这是 [初步方向稿](GAME_CLIENT_PERSONA_DIRECTION.md) 的第一阶段：人格与交流策略接入。
没有新增自主开发工具、长期自身状态、跨群情绪状态或定时承诺系统。

角色保留小鲸鱼的昵称与蓝白网络形象，定位为成年女性、中级 Unity / C# 客户端工程师，
偏玩法与战斗逻辑、资源加载和性能分析。职业背景是虚构设定，不冒充真实员工，
不把读过资料写成已运行实验。

## 选择与保存

1. 在控制台打开“设置 -> 人设 -> 选择人设”。
2. 选择“小鲸鱼（游戏客户端开发者）”。
3. 确认“交流策略”为“自然可靠”，按需调整正文与管理员附加规则。
4. 点击“保存人设修改”。

选择模板只填入草稿，保存才生效。机器人名字、群内展示名和参与度保留现有设置，
不会因为选择模板被重置。角色修改适用于之后新建的模型请求，不撤回在途请求或已发送消息。

旧版“小鲸鱼（默认）”和默认配置保持不变，更新代码不会强制切换现有实例。
改回旧模板并保存即可恢复原版交流策略。可以用“添加人设”以当前草稿为基础创建自定义副本；
正文、附加规则和交流策略随副本一起保存。

修改 Markdown 源文件会更新下一次启动加载的内置模板，但不覆盖已经保存到配置的角色正文。
更新角色后，需要在控制台重新选择模板并保存；有自定义修改时先保留副本。

## 架构与兼容

新增配置字段：

```json
{
  "persona": {
    "behaviorProfile": "grounded"
  }
}
```

- `legacy`：旧版策略，缺少字段时默认使用；旧版提示词输出保持兼容。
- `grounded`：自然可靠策略，允许技术说明的必要长度、编号和代码，取消通用规则中
  鼓励装傻乱答、固定短句上限和按轮数凑表情的要求。
- 非法策略值在配置保存与创建模板 API 中被拒绝，不写入配置。
- 管理端 `GET /api/persona-templates` 返回每个模板的 `behaviorProfile`。
  创建自定义模板时可传同名字段，旧客户端省略该字段仍得到 `legacy`。

角色正文通过现有配置同时进入群聊、私聊、每日动态、动态互动和好友评估。
`grounded` 只替换普通聊天的风格策略，其他场景仍使用独立工具协议，不额外注入群聊流程。
安全边界、当前会话绑定、观察模式、白名单、时间控制与未知发送结果保护都继续有效。

生命周期会因实际系统提示变化而在下一次请求重新建立上下文前缀；已有检查点仍按原机制处理。
历史角色的无来源经历不应因此变成新角色事实，角色卡要求区分事实、设定和推测。

## 技术内容发送

自然可靠策略使用 Markdown 代码围栏或行内反引号标明代码。发送层在处理普通文本格式前保护代码，
只去围栏，保留缩进、换行与 `*`、`>`、`|`、下划线等内容。
整段代码尽量放在同一个气泡，超长内容仍遵循原有 QQ 消息长度限制。

代码保护由当前 Agent Session 的策略快照决定，不接受群友自定义工具权限；
即使运行途中管理员切换人设，本轮也保持原先发送约定。旧版发送格式不变。

模型仍然没有执行代码、读取宿主机文件或实际操作引擎的工具。代码仅是未经运行的建议，
不能声称完成构建或测试；会话交接也不是定时任务。
