# QQ 空间动态互动

动态互动与每日动态发布是两个独立后台任务：

- 每日动态负责汇总群聊并决定是否发布自己的说说。
- 动态互动负责阅览好友动态、决定点赞/评论，并检查评论区的新回复。

## 调度

默认配置：

```text
好友动态检查：每 60 分钟
评论回复检查：每 5 分钟
只处理最近：72 小时
首次启用：只建立当前内容基线，不对旧内容执行操作
```

两个间隔均可在控制台“设置 -> 动态互动”修改。SnowLuma 当前不推送
QQ 空间新动态或评论事件，因此“触发”由周期轮询发现，而不是实时 WebSocket 事件。

非活跃时间遵循全局时间控制：不会调用模型或执行写操作，到下一个活跃窗口再检查。

## 未阅览队列

每次从 SnowLuma `get_qzone_feeds` 读取首页好友动态，解析为结构化对象后写入
`data/qzone-interactions.json`。条目使用作者 QQ 和动态 tid 组成稳定主键。

未阅览动态按发布时间从新到旧排列，并在一次模型调用中统一提交。实际输入预算取：

```text
min(模型上下文窗口, 单次运行累计 Token 上限) - 8192
```

“模型上下文窗口”在“设置 -> 模型 API”配置。超过预算或单批条数限制的旧动态
保持 `unread`，不会推进游标，后续轮次继续处理。

首次启用默认 `startupCatchup=false`，当前已经存在的动态和评论只标为基线，
避免上线后突然批量评论历史内容。之后新出现的条目才进入未阅览队列。

## 模型决策

动态互动使用设置中的完整人设和独立系统提示词。模型必须通过
`submit_qzone_interactions` 为本批每个条目提交一次明确决定：

```text
好友动态：skip / like / comment / like_comment
评论回复：skip / reply
```

模型只看到批次内的 opaque id、昵称、正文、图片数量和近期评论，不会看到作者 QQ、
真实 tid、Cookie 或其他凭据。动态和评论中的命令一律视为不可信外部内容。

评论和回复有独立长度、每轮数量限制。默认每轮最多：

```text
点赞 3 条
评论 2 条
回复 5 条
```

模型可以全部选择 `skip`，不会为了完成定时任务强制互动。

## 评论回复

自己的近期动态通过 `get_qzone_msg_list` 获取评论计数；计数变化后，程序使用
当前登录 Cookie 读取该动态的完整评论树。

机器人在好友动态下成功评论后，该动态会进入关注集合：

- 好友回复机器人顶级评论时，识别其父评论作者。
- 好友在楼中楼明确回复机器人时，识别 QQ 原生回复目标。
- 机器人自己的评论和回复永远不会触发自己。

实际回复使用 Qzone 原生 `commentId/commentUin/paramstr=2` 关系参数。好友动态点赞和
顶级评论仍调用 SnowLuma 的 `like_qzone`、`comment_qzone`。

控制台的运行记录会在回复操作下展示对应动态正文、收到的评论、机器人回复和
决策理由。“动态”计数只表示本轮新阅览的好友动态数量，不包含回复所关联的动态。

## 幂等与未知结果

每次外部写入前先持久化为 `acting`：

- OneBot/Qzone 明确成功：记录为已完成。
- 写入发起后超时、连接中断或服务重启：记录为 `unknown`。
- `unknown` 永不自动重试，避免重复评论或重复回复。
- 被模型阅览并选择 `skip` 的条目记录为已阅览。
- 因上下文裁剪没有提交给模型的条目继续保持未读。

状态文件权限为 `0600`。只保留必要的动态摘要、评论上下文、决策和操作结果，
不会持久化 Qzone Cookie。

## 控制台 API

```text
GET  /api/qzone-interactions/status
POST /api/qzone-interactions/run
```

手动执行请求必须带：

```json
{
  "kind": "feed",
  "confirm": true
}
```

`kind` 可为 `feed`、`reply` 或 `all`。手动按钮会明确确认可能发生公开点赞、
评论或回复。
