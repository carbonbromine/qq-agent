# 每日动态：人设与发布

## 人设从哪里来

每次生成读取“设置 -> 人设”的 `botName`、`selfNickname`、完整 `roleText` 和
`customRules`。不截取角色卡前几段，不使用固定的小鲸鱼口癖覆盖用户人设。
人格保持不变，表达场景从“群聊接话”切换到“自己的 QQ 空间”。

实现位于 `src/moment-prompt.js`，提示词版本为 `persona-moment-v2`。
角色卡和附加规则有指纹；发布旧草稿时如果人设发生变化，必须重新生成。

## 提示词设计

单纯要求“像真人、符合人设”不够具体，容易出现通用感悟文案加几个口头禅。
反过来，直接复用群聊的完整 system prompt，会夹带发送气泡、回复艾特、
调用 finish 等操作规则，与写说说的任务冲突。

新的提示词分成以下层次：

1. **完整人设**：保留身份、自我认知、偏好、价值判断、关系边界和语言习惯。
2. **当前场景**：不是客服回复，也不是给管理员交总结；由角色选择自己在意的一件事。
3. **具体触动**：先有一个细节、反差、疑问或情绪，再产生第一人称反应，而非串联所有群话题。
4. **自然表达**：篇幅服从人设；允许短句、留白、不完整背景，不强制笑话、互动问句或结尾升华。
5. **真实性**：区分本人行为与他人经历，不把围观说成亲历；研究必须有真实工具结果支撑。
6. **隐私与配图**：不公开可识别的私域细节，不选私密截图；配图必须先看过且与正文有关。
7. **明确决定**：可以 publish，也可以 skip；必须通过有效工具参数提交，不能用空白或解析错误冒充“不想发”。

随机方向只作为可忽略的灵感，放在动态输入中。稳定的人设和写作规则放在前缀，
有助于复用缓存。最近已发布内容提供给模型，减少重复选题和重复开场。

核心约束包括：

> 让人设决定你注意什么、站什么立场、用什么语气，不要在一段通用文案上贴几个口头禅充当人设。
>
> 不要把每个小插曲拔高成生活哲理，不自动加治愈、感悟、金句或说教式结尾；话说完就停。
>
> 材料没有证据，不能把别人的经历写成“我折腾了三小时”。研究是为了满足自己的好奇，不是自动生成百科报告。

这仍是生成模型，不保证每次文风都完美；后台预览可以查看真实正文、群摘要和完整模型输入。

## 发布状态

| 状态 | 含义 | 后续操作 |
|---|---|---|
| 生成中 | 正在收集资料或生成 | 等待，不同时启动第二个任务 |
| 草稿 | 未对外发布 | 发布这份草稿，或生成新草稿 |
| 决定不发布 | 模型有效提交了 skip 和理由 | 可手动重新生成；定时任务不会不断重试 |
| 生成失败 | 参数无效、模型错误或发布前检查失败 | 查看错误；可重新生成 |
| 生成已中断 | 服务在生成阶段停止 | 可以重新生成，不会锁住整天 |
| 等待活跃时间 | 时间控制阻止模型运行 | 遵循时间窗口 |
| 发布中 | 已准备发起外部写入 | 禁止再发 |
| 已发布 | 返回了有效 tid，或在空间核对到相同内容 | 不重复发 |
| 发布结果待核对 | 请求超时、无 tid，或发送中重启 | 只读核对空间；未找到也不能证明未发布 |

非法 JSON/不完整字段会作为工具错误反馈给模型，在最大轮次内纠正。
无法完成时记录真实失败及已消耗用量，不悄悄变成 skip。
已发布或不确定记录按日期阻止重复发布；普通失败和中断不妨碍手动重新生成。

`发布这份草稿` 不调用模型，使用保存的正文和已看过的图片引用。
发布前重新核对人设、登录账号、运行模式、时间控制、白名单与重复内容；
配图地址重新获取并下载为 base64。图片不可用时记录原因并可降为纯文字。
发布结果必须带 tid；网络异常不会自动重发。

## API

- `GET /api/daily-moments/status`：状态和最近记录。
- `POST /api/daily-moments/run`：生成；`publish=false` 为预览，
  `publish=true, confirm=true` 为生成后按模型决定执行。
- `POST /api/daily-moments/records/:id/publish`：`confirm=true` 发布指定草稿。
- `POST /api/daily-moments/records/:id/reconcile`：只读核对不确定的发布结果，不重新发送。
